# Data Prepper Sample Schemas

This directory contains sample JSON schemas that represent the structure that would be generated by the data-prepper project. These schemas are used for validation to ensure consistency between the JSON documentation files and the actual plugin schemas.

## Directory Structure

```
sample-schemas/
├── processors/     # Sample schemas for processor plugins
├── sources/        # Sample schemas for source plugins  
├── sinks/          # Sample schemas for sink plugins
└── buffers/        # Sample schemas for buffer plugins
```

## Schema Format

Each sample schema file follows this structure:

```json
{
  "name": "plugin-name",
  "plugin_type": "processor|source|sink|buffer",
  "properties": {
    "property_name": {
      "type": "string|boolean|integer|number|array|object",
      "required": true|false,
      "default": "default_value",
      "items": {
        "type": "string"
      },
      "properties": {
        // Nested properties for object types
      }
    }
  }
}
```

## Validation

Use the schema consistency validation script to compare documentation with schemas:

```bash
ruby _script/validate-schema-consistency.rb
```

This will:
- Compare JSON documentation files with corresponding sample schemas
- Report missing properties in documentation
- Detect type mismatches between schema and documentation
- Identify extra properties in documentation not present in schema
- Generate coverage reports for each plugin

## Creating Sample Schemas

When adding new plugin documentation:

1. Create the JSON documentation file in `_data/data-prepper/{plugin_type}/`
2. Create a corresponding sample schema in `sample-schemas/{plugin_type}/`
3. Run the validation script to ensure consistency

If no sample schema exists, the validation script will automatically generate one based on the documentation structure and place it in the appropriate directory.

## Schema vs Documentation Separation

- **Sample Schemas**: Represent the authoritative structure from data-prepper project
  - Property names, types, required fields, defaults
  - No descriptions or examples
  
- **JSON Documentation**: Contains the descriptive content
  - Descriptions, examples, HTML formatting
  - Must align with schema structure

This separation allows both projects to evolve independently while maintaining consistency through validation.
